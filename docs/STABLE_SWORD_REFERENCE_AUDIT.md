# SWORD verse-index compatibility: mandatory publication proof

Every **approved Bible** must declare `index_audit` in its validated module metadata. `scripts/validate.py` checks this for each approved module. This check is independent from the original source validation, the full text/notes/layout fidelity review, and the frontend acceptance test.

## Two generic evidence paths

### `stock_reader_keys` — preferred for new releases

The reused [historical PR #23](https://github.com/icfmp/Bible-Resources/pull/23) checker `scripts/stable_sword_refs.py` compares authorial source verse-key inventory against the actual resolved compiled reader keys and the installed stable SWORD versification registry. Its reviewed-merger path requires a distinct original-publisher digest, an exact source-bound `SOURCE_REFERENCE_MERGES.json`, full source/readback body evidence, exact module payload SHA-256, stable released SWORD engine/version and human sign-off. `SWORD_COMPATIBILITY.json` must be generated by an independent real-source/stock-reader audit. No automatic verse insertion, fallback to HEAD, or silently accepted remapping is permitted.

Using this method requires `"index_audit": {"mode": "stock_reader_keys"}` in metadata, plus the proof and (only if used) original approved merge policy. Existing synthetic regressions cover missing, duplicated, out-of-registry, nonadjacent and unapproved mappings, stale hashes and unsupported runtimes.

**Limit:** this proof checker consumes inventories produced independently; it is not itself an inventory extractor. The general-purpose producer, independently proven on a second real Bible, remains part of [issue #28](https://github.com/icfmp/Bible-Resources/issues/28).

### `published_source_audit` — migration of an already released edition

For previously published modules with an **immutable audited release**, use a reviewable metadata declaration such as:

```json
{
  "index_audit": {
    "mode": "published_source_audit",
    "manifest": "config/release-name.json"
  }
}
```

The generic `scripts/published_reference_audit.py` revalidates the entire original source-audit SHA-256 against the release manifest **and source-validation receipt**, the source/output revision, all published SWORD payload member hashes, original verse counts across all books and chapters, classified source-only and empty reader-only entries, exact observed adjacent merges, the original source-bound approval policy and its SHA-256, and the recorded isolated reader reinstallation.

The existing Louis Segond 1910 0.1.0 uses this compatibility path because its exact released asset and real stock-reader/source evidence were validated **before** the modern standard `SWORD_COMPATIBILITY.json` format existed. The approval explicitly merges Mark 10:52–53 in the reader's 52 entry while retaining full source text; Job 34:37 is an unoccupied SWORD registry slot, not added Scripture. No identifiers or verse counts are hardcoded in generic validation.

**Limit:** this is a *cryptographically pinned revalidation of a previously executed audit*, **not** a fresh 31,170-verse reread by current CI or a general replacement for new source-to-reader audit execution. The original audit is available alongside the [LSG 0.1.0 GitHub Release](https://github.com/icfmp/Bible-Resources/releases/tag/lsg-0.1.0) and is only meaningful when the entire identity/approval chain matches. It does not infer that the original source's textual or editorial decisions are infallible.

## Required validation

```sh
python -m unittest discover -s tests -v
python scripts/validate.py
python scripts/build.py --output dist
python scripts/smoke.py
```

The real repository CI installs stock `diatheke` and performs those tests. Tests reject mutated files, missing approvals, stale source/audit/payload fingerprints and independently unclassified changes. Production module bytes and the published package are never rewritten by this gate.

## Independent authorial OSIS index producer (first stage)

The new [source OSIS inventory](SOURCE_OSIS_INVENTORY.md) provides a source-only, text-free `book.chapter.verse` key list and SHA-bound receipt after the independently validated OSIS source is available. It supports container and milestone verses with fail-closed duplicate/missing milestone detection and preserves editorial numeric gaps. It **does not** claim an original USFM/USFX-to-OSIS audit or stock-SWORD reader-key extraction; those and a second real edition remain pending in #28.

## Independently collected actual native reader index

The [native stable-SWORD inventory producer](NATIVE_SWORD_INDEX_INVENTORY.md) uses the stock `libsword` module's own `VerseKey` and `hasEntry` methods to enumerate **actual populated keys**, the full installed versification chapter ceilings and occupied book/chapter intros. A separate [OSIS source producer](SOURCE_OSIS_INVENTORY.md) outputs the independently authored source key list. Their outputs feed the existing fail-closed comparison, but **do not** by themselves certify source conversion, the full text/notes/layout or editorial approval. The real published LSG RawText module is exercised against its immutable original audit in CI. A second real zText/other edition and complete content preservation remain unverified.

## Remaining multi-translation work

The reusable guard is now implemented, but a separate generic *producer* must still capture source and reader inventories from original and compiled real modules; test a second Bible with different notes/driver/versification; and expand full original content, annotation and layout fidelity checks. Follow [issue #28](https://github.com/icfmp/Bible-Resources/issues/28). Do not claim these future capabilities already exist.
