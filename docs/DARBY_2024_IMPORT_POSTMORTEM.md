## Where time went

**The dominant calendar bottleneck was stage 4, not the two-minute final compilation.** The owner observed approximately one day of elapsed work with multiple interrupted chat sessions before the source/native proof was finished. This is *wall time across analysis, changing tests, Actions queue times, editor triage, retries and conversation interruptions*, **not** one 24-hour CI execution. [The Darby import tracker](https://github.com/icfmp/Bible-Resources/issues/62) has 223 issue comments across all stages, many of them intermediate evidence updates; **223 must not be reported as 223 individual full audits**.

Root causes, in order of costly iteration:

1. **Wrong entry gate and exhaustive reruns.** Original eBible's stock SWORD had lost the original **footnote caller letters** despite broadly readable numbered Scripture and note bodies. Early full indexed/main-text checks did not disqualify unchanged reuse. Subsequent structural/whitespace, linebreak, paragraph/poetry start/end and annotation checks repeatedly scanned the entire corpus while the stock candidate was already materially incomplete.
2. **Source/native event-model differences.** USFX paragraph/poetry XML containers and actual stock SWORD OSIS `sID/eID` milestones do not necessarily share a literal one-to-one representation. Word-relative positions, punctuation boundaries, verse-zero book introductions, authorial text/tail newline provenance, different source/native verse-record scope and missing explicit anchors each required careful distinction rather than pretending count equality proved semantic equality. The expensive investigation was needed to *discover* robust rules; it should not be repeated manually on future editions.
3. **Important defects outside main text.** Machine note targets included wrong or unaddressable destinations and references explaining intentionally **absent** verses. Those defects were not solved by comparing Bible wording or by a passing SWORD parser; reviewers had to distinguish editorial decisions, technical source defects and reader bugs.
4. **Non-byte-preserving XML serialization.** Reconstructing a candidate with a generic XML serializer caused an independently observed four-line Psalm 150 poetry loss in the compiled result; the fix was a byte-preserving, strictly source-SHA-bound overlay, not accepting lost text. A source-to-compiled semantic audit alone is not an excuse to alter source layout.
5. **External CI interruptions.** On 2026-11-11, Ubuntu mirror DNS failures wasted **486 seconds** in [Validate #43049785860](https://github.com/icfmp/Bible-Resources/actions/runs/43049785860), and **405 seconds** in the [stage workflow #43049785798](https://github.com/icfmp/Bible-Resources/actions/runs/43049785798). Both failed before meaningful full source/native checks. Those are network failures, **not** Bible fidelity failures.
6. **Publication integration exceptions.** A fully source-audited release run later failed on direct `main` push due to mandatory GitHub PR protection (`GH013`); the correct solution was a two-phase protected release branch/PR and separate immutable finalizer, **not bypassing protection**. A distinct promoted ZIP wrapper and catalogue-built ZIP wrapper had different overall SHA-256 while preserving all seven decompressed SWORD file bytes; the workflow now verifies each member and uses the deterministic catalogue-built ZIP as the single public Release/Pages identity. See [#169](https://github.com/icfmp/Bible-Resources/pull/169), [#170](https://github.com/icfmp/Bible-Resources/pull/170).

These are separate causes: **a successful compile**, **machine fidelity evidence**, **reader verification**, **owner editorial sign-off** and **actual public delivery** cannot be conflated.

## Implemented generically in main — PR #171

[PR #171](https://github.com/icfmp/Bible-Resources/pull/171) consolidated older unfinished stacked PRs #137, #138, #139; all three obsolete PRs are now closed.

- **Fast rejection before full stage 4**: the existing strict original-archive SHA checks first read up to 12 *authorial* USFX note-bearing source references, selected across actual books. The real native SWORD single-verse reader checks original note body/count before trusting note caller/type comparisons. **Provable** missing/changed literal callers or unambiguous reference-note kind mismatches reject *unchanged stock reuse immediately*. Inconclusive proof must continue the deeper audit. One real pinned Darby original was disqualified on the first verse sample.
- **Full material-loss classification**: for modules not eliminated early, independently compare source/native numbered note bodies, original literal caller `n`, note kinds, explicitly authored machine targets and positional diagnostics. Material loss blocks stock reuse even if all main Bible words match; no fabricated approvals.
- **One source/native scan for stages 4 and 5**: opt-in `/bible-audit <resource-id> 4-5` or Actions `stage=4-5`. The stages produce **independent** machine receipts, but share one exact-SHA-validated acquisition and one real scanner invocation. Existing 4 and 5 invocations remain available. A blocked stage stays blocked; no human checklist is automatically ticked.
- **Safe resumability at issue level**: metadata-only report and bounded, stable review categories, Action run links, exact commit and source/archive SHA checks survive chat interruption. A successful Action can still report `BLOCKED`; an empty anomaly list is never publication/editorial authorization.
- **Synthetic regressions + two real stock-read gates**: every new behavior has synthetic unit tests. The [real separate stage-4 run](https://github.com/icfmp/Bible-Resources/actions/runs/43250311443) and [real combined 4+5 run](https://github.com/icfmp/Bible-Resources/actions/runs/43250743318) correctly exercise the original BPC/eBible edition failure without leaking Bible text or notes.

## Remaining high-return improvements — not falsely marked completed

1. **P1: Versioned independent 4a/4b/4c/4d receipts and dependency-aware resumption** ([#83](https://github.com/icfmp/Bible-Resources/issues/83)). Each subcheck needs both immutable original/source and stock-module digests, full manifest digest, tool commit + Action run, prerequisites and bounded metadata. Reuse **only** where exact source, module, logic and dependencies match. Incomplete source/nav evidence must remain `PARTIAL`/`BLOCKED`, never `DONE`.
2. **P1: Stronger generic semantic structure pairing** ([#28](https://github.com/icfmp/Bible-Resources/issues/28), [#83](https://github.com/icfmp/Bible-Resources/issues/83)). Independently prove matching original/native paragraph/poetry **open AND close** word/punctuation-relative coordinates, cross-verse and verse-zero boundaries. Synthetic cases must catch moved/duplicated/swapped closes and same-count/same-order shifts. Do not equate renderer-specific tags with original exact markup.
3. **P1: Per-format source conversion parity** (#28). Original OSIS, USFX and USFM do not support identical conversion proofs; select reviewed adapters and audit each actual source→converted→SWORD hop. Native stock reuse needs source→stock parity; it must not be rebuilt merely to fit a test.
4. **P2: Review queue and second-edition tests** (#83). Group only unresolved safe references/counts for editorial action; try the exact same code on another independently rights-cleared original while refusing stale upstream ZIP pins.
5. **P2: Generic source-attested release PR builder** (#28). The successful Darby release's protected-branch + immutable SHA/Pages strategy should become a reusable release plan parameterized by edition, rather than copying its Darby-specific workflows. Do not merge, approve rights or publish from a mere CI success.

**Guardrail:** No automated decision may license a text, change a verse/critical note, silently fix an author's punctuation, erase a true discrepancy, or approve publication. A next-edition audit should stop as cheaply as possible **when source loss is proved**, then continue to full source/native/real-reader/editorial review only on a viable candidate.
