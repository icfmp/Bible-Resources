## Editorial decisions

### A. Accept as *proposed index-only corrections*: 17 authorial section ranges / 24 verse aliases

The original CrossWire commentary body itself identifies the intended passages, the missing indices are genuinely empty in the original KJV SWORD registry, and a separately compiled module links the newly reachable verses to **exactly the same original master record**. Source-body words, headings, citations, attributes and original entry locations must remain unchanged.

**16 contiguous two-verse cases.** Independent CCEL ThML supplies both the exact citation range and a leading section paragraph that shares at least 20 consecutive exposition words with the actual original CrossWire passage for **16/16** cases. This corroborates *where the same commentary should be reachable*, **not** whether each CCEL annotation/wording is interchangeable with CrossWire. The precise locations are in [reviewed link decision data](../../../../config/commentary-intake/mhcc-crosswire-reviewed-links.json), and the evidence measurements in [the editorial census](editorial-section-scope-audit.md).

**1 discontinuous case — Matthew 13.24–30 and 13.36–43.** The exact original CrossWire heading explicitly identifies **both** ranges. Two independent digital presentations ([Biblia](https://biblia.com/books/mhenryc/Mt13.1-23) and [EGW](https://m.egwwritings.org/en/book/14168.7598)) corroborate the disjoint section grouping. The original independently authored Matthew 13.31–35 entry remains **unlinked** to this section. Never replace the real disjoint scope by a fabricated continuous Matthew 13.24–43 range. Unlike the other 16, this case does **not** have an exact matching CCEL ThML source `scripRef` for the combined disjoint passage; that limitation is explicit in the decision data and audit.

The plan is now checked against the actual ZIP digest, complete native original occupied-key SHA-256 map, actual KJV verse registry, all independently corroborating source-lead cases and all 17 existing native heading omissions **before** any temporary module compilation. It rejects altered scopes, uncorroborated leading excerpts, conflicts with original sections, edits to existing K keys and any attempt to include chapter-wide guesses. Reproducing the same 24-key proposal by a separate source-first method removes a significant circularity in the original heading-only diagnostic.

**Provisional scope acceptability is not a release authorization.** Source association is a documented editorial judgement based on this exact digital witness and source comparisons. Historical print-edition equivalence has not been established.

### B. Retain CrossWire annotations unchanged: 25 CCEL-only hyperlink targets

The 25 cases across 20 originally single-key chapters are a **difference between independent digital editions**, not 25 proven errors. Their original source hyperlink labels are (a) present as unlinked CrossWire prose: **18**; (b) inside another already-existing CrossWire `reference` element with a different target: **1**; (c) surviving only with punctuation/markup differences: **3**; or (d) absent from that CrossWire selected entry: **3**. Only 14 of the 18 plain-text labels are unique. There is no independently verified original CrossWire master target to restore, no proof that the differing CCEL target/annotation is authorial, and no established permission to import separately created digital enhancements.

**Decision for 0.1.1: do not insert, delete, retarget or silently normalize any `reference` element.** Preserve all CrossWire XML and OSIS reference attributes exactly under the existing readback invariants. This is a definite **no-change editorial disposition** for the current correction scope, not an assertion that all links are perfect. Retain the 20-case evidence table as a separate future research queue if an authoritative *edition-matched* source becomes available; do not make it a false blocker for the 24 index repairs.

### C. Preserve original chapter-only indexing pending separate reader-oriented scope policy

The **118** first-verse-only chapter K entries are **not** 118 demonstrated textual defects: 116 align with undivided chapter source divisions; the other two are traceable to an unwrapped book-level chapter-one paragraph (**2 Chronicles 1**) and an additional CrossWire book heading (**Nehemiah 1**). No missing authorial chapter exposition was demonstrated for those cases, and their original I entries contain no additional independent commentary prose. Source structure alone does not prove an instruction to create **2,285** additional verse aliases, which can substantially increase whole-chapter reader repetition.

**Decision for 0.1.1: do not expand these 118 chapters automatically.** Keep the independently researched full-chapter navigation improvement separate, to avoid turning a focused 24-key repair into a much larger editorial and reader presentation change.

The existing Lev 19 and Ps 108 intro-only cases also remain unchanged and must never be silently converted into K entries. Existing 29,975 original occupied native I/K/TOP keys remain preserved.

## Non-negotiable correction checks

1. Actual released `osis2mod` compiles a new **separately identified** module from the original CrossWire raw-entry contents; do not alter upstream `MHCC` or the published `BRMHCC` 0.1.0 package in place.
2. All **28,718** original numbered K keys, **1,255** original I keys and **2** opaque TOP positions remain present, with all existing visible Unicode words, punctuation (modulo whitespace-only transport), source XML element/attributes and ordered `reference` destinations preserved in complete native readback. Raw byte equality is **not** claimed when the standard compiler adds OSIS wrappers.
3. Exactly **24** new K index keys, linked to their existing master body, and **zero** other additions or omissions. All new links must pass native `SWModule::isLinked` checks; adjacent original section identities must remain unchanged, especially independently authored sections.
4. Actual selected-verse reader smoke tests must succeed, and whole-chapter repeated display must be recorded as a **reader behavior**, not an invented duplicate source entry. The authentic Xiphos selected-verse sample previously passed **3/3**; its complete whole-chapter deduplication proof remains **inconclusive**. The command-line `diatheke` chapter probe demonstrates repeated rendering of linked records. Reader limitations should not cause unfaithful source alteration.
5. Only after the owner separately authorizes publication: prepare a **new versioned BRMHCC 0.1.1** header, package checksum, licence/provenance statement, release notes, catalogue update and installation/update smoke test. No existing tagged asset, source ZIP or published package should be overwritten.
