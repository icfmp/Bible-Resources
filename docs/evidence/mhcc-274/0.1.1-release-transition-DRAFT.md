# MHCC 0.1.1 — renamed SWORD identity, version migration and rollback (draft)

**No new release, no content change, no owner publication approval.**
This is a technical transition specification for a future approved
release, not an activated release plan or catalogue entry.

## Current identity and proposed new SWORD ID

The project owner explicitly requested renaming the **new corrected edition**
from `BRMHCC` to `MHCC` on 2026-11-16. The proposed **0.1.1** module therefore
uses `[MHCC]`, `mods.d/mhcc.conf` and
`DataPath=./modules/comments/zcom/mhcc/`. Retain the existing
`modules/mhcc-crosswire` directory, `mhcc-crosswire` curated ID and
`matthew-henry-concise-crosswire-2.0` source lineage. The SWORD ID,
unlike the curated ID, **changes** from `BRMHCC` to `MHCC`.
The same single catalogue row will ultimately use `sword_id=MHCC`
and `sword/packages/MHCC.zip`; neither catalogue nor old ZIP URL is
changed by this private draft. The corrected format remains standard
`zCom` / KJV with `BlockType=CHAPTER`.

**SWORD collision / migration is a real consequence, not a cosmetic rename:**

- CrossWire already distributes an original module with SWORD ID `MHCC`
  (upstream version `2.0`). In a single SWORD module library, the new
  edited `MHCC` **cannot coexist** with that original under the same
  identifier. Installation/update requires an intentional replacement
  decision and must not silently conflate the two providers or imply
  the new curated `0.1.1` sorts newer than upstream `2.0`.
- Existing installations of the **Bible Resources** `BRMHCC 0.1.0`
  use a *different* SWORD ID. A new `MHCC` archive does **not**
  automatically uninstall `BRMHCC`, transfer preferences, or migrate
  readers' per-module state. Record an explicit removal/migration
  instruction and separately verify application behavior before presenting
  the change as an in-place upgrade. This repository must not alter the
  Bible application's code.
- The archived `mhcc-0.1.0` GitHub Release contains the original
  `BRMHCC-0.1.0.zip`, not `MHCC-0.1.0.zip`. Never rename/rewrite its
  files, bytes or approved historical release plan. The new release tag
  may be `mhcc-0.1.1` and its immutable **new** asset name will be
  `MHCC-0.1.1.zip` only after exact staged payload/rights and separate
  publication approvals.
- Reversible private identity-only rekeying changes exactly the SWORD
  section header and DataPath; the real corrected-source SWORD rebuild
  must still prove complete native I/K/TOP equality and no accidental
  duplicate module load. Never use a same-ID provider collision as a
  reason to modify commentary text or section divisions.

These compatibility consequences are a separate explicit release-readiness
check; private SWORD/Xiphos success alone cannot establish user-side migration
or provider update behavior.

## Plan and descriptive profile transition

The current active plan is `config/release-plans/mhcc-0.1.0.json`,
not a legacy-binding record. It must be **removed from the current
plan directory** when an approved `mhcc-0.1.1.json` plan is added.
Two active plans for the same module fail closed. The previous plan
persists in immutable Git history, and GitHub release
`mhcc-0.1.0`/`BRMHCC-0.1.0.zip` remains available for rollback.

The existing English reader profile is approved specifically for
version 0.1.0 and claims that original source words and references
are untouched. The current schema rejects that approval when the
module version advances. Publish 0.1.1 with a **new separately
approved description** based on
[the draft](0.1.1-reader-profile-DRAFT.md), or omit the optional
profile until approved. Do not re-label the 0.1.0 approval as current.
