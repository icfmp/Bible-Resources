# MHC — overlapping authorial commentary sections

**Accepted technical conclusion:** the original CrossWire authored OSIS contains genuinely overlapping commentary section scopes. The final [MHC 0.1.0 release](../releases/MHC-0.1.0.md) preserved the complete authored prose using source-attested verse indexing and chapter-introduction semantics. This file is not a proposal for a proprietary sidecar.

## The distinction

The early source probe located **seven shared verse addresses** involving **14 original authored section assignments**. These were not automatically seven theological subverse units. Most could be corrected to independently reviewed whole-verse boundaries without deleting prose.

Two cases required particular attention:
- **Romans 4:9–16 / 4:17–22:** use source-attested whole-verse section indexing, preserving both authored comment streams and their correct adjoining scopes; do not invent a second verse-17 entry.
- **2 Chronicles 1:** preserve the author's real chapter preface as an independently addressable **chapter introduction** while leaving the verse 1 exposition separate. A reader that shows this preface only through its chapter-heading menu has a presentation limitation, not missing Scripture/commentary source content.

The reviewed transformations include **six overlap/navigation groups and one introduction reclassification**. Exact source and new hashes are in [`CLEANUP_MANIFEST.json`](../../CLEANUP_MANIFEST.json). Native [proof #44501242523](https://github.com/icfmp/Bible-Resources/actions/runs/44501242523) and [Xiphos chapter introduction proof #44539128176](https://github.com/icfmp/Bible-Resources/actions/runs/44539128176) are separate evidence.

## Safeguard

Do not derive authorial identity from identical rendered words or from a shared SWORD key alone. Do not duplicate, merge or rename source units to satisfy a GUI. If an independent reader cannot represent disjoint original scope correctly, document that reader limitation and handle it at the application layer where possible.

Historical dual-owner prototype layouts and their intermediate seven-to-two counts remain recoverable from Git history; **they are not current release instructions**.
